# 동시성 제어 방식 보고서

- 사용한 스레드 : newFixedThreadPool
- 고정된 스레드 개수의 풀 : 20
- 쓰레드 실행 요청 개수 : 60

1. ConcurrentHashMap 사용하여 순서 보장
2.  synchronized 을 사용하여 먼저 시도
3.  ReentrantLock으로 변경
4. 응답 시간 비교 결과 성능상 별 차이는 없으나 동작 원리에 차이
    
    ```sql
    ============ synchronized 응답 시간 결과 ============
    총 실행 시간(ms): 22965
    스레드당 평균 처리 시간(ms): 382.75
    기대 금액 : 60000
    실제 금액 : 60000
    ```
    
    ```sql
    ============ ReentrantLock 응답 시간 결과 ============
    총 실행 시간(ms): 22809
    스레드당 평균 처리 시간(ms): 380.15
    기대 금액 : 60000
    실제 금액 : 60000
    ```

5. 결론
- synchronized의 경우 구현이 간단하지만 락 제어를 할 수 없기때문에 관리 측면에서는 ReentrantLock이 편리하다.
- 다만 타임아웃 관리, 공정 락 설정등 락 제어에 있어서 ReentrantLock이 사용하는 것이 더 좋다.
- ConcurrentHashMap은 HashMap과 달리 순서를 보장한다. 다만 lock이 자동으로 제거가 되지 않기떄문에 요청이 점차 많아질 경우를 대비해서 스케줄링을 통해 락 정리가 필요하다.
